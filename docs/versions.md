## 1. 対応しているリリース

Windows 版のツールが公開されている、次の 33 リリースに対応しています。すべて実際にダウンロードして、テストを通しています。

| 系列 | リリース | コンパイル結果のバイナリのバージョン |
|---|---|---|
| 1.5 系 | 1.50RC1、1.50RC2、1.51 | 1500 |
| 1.6 系 | 1.60、1.60b、1.60c、1.60d、1.60e、1.61a、1.61b、1.61c、1.61e、1.62、1.62a、1.62b、1.62c、1.62d、1.62e | 1610 |
| 1.7 系 | 1.70、1.70a、1.70b、1.70e、1.7.3.0 | 1710 |
| 1.80 系 | 1.80.0（RC1、RC2、RC3）、1.80.1、1.80.2、1.80.3、1.80.4、1.80.5、1.80.6、1.80.7 | 1810 |

対応していないもの:

- ベータ版（1.50Beta、1.60Beta、1.70Beta、1.8.0.0-beta など）
- 1.43 以前（Effekseer の GitHub リリースに Windows 版ツールが無く、テストしていません。古いファイルの読み込み・編集はできます）
- 1.80.7 より新しいバージョン（公開されたら対応を検討します。[Issues](https://github.com/ramasuke/EffekseerEfkprojTool/issues) で知らせてください）

同じ系列のリリースは、設定できる値の範囲もコンパイル結果の形式も同じです。そのため、ツールは**系列ごと**に動作を切り替えます。

## 2. 使うバージョンの決まり方

1. `--effekseer-version`（コマンドのオプション）
2. 環境変数 `EFFEKSEER_VERSION`
3. 設定ファイルの `effekseer.version`
4. どれも無ければ、見つかった `Effekseer.exe` のバージョン
5. それも無ければ `1.7.3.0`

`Effekseer.exe` のバージョンは、同じフォルダ（1.80 系は `bin` フォルダ）にある `EffekseerCore.dll` から判定します
（`Effekseer.exe` 自体のファイルのバージョン情報は `1.0.0.0` で、使えません）。
この判定は全リリースで正しいバージョンを返します。ただし 1.50RC1 と 1.50RC2 だけは `1.50` と判定されます（系列は正しく判定されます）。

使う `Effekseer.exe` は、`--cui-path` → 環境変数 `EFFEKSEER_CUI` → `effekseer.cui_paths` → `effekseer.cui_path` の順に探します。
`effekseer.cui_paths` では、使うバージョンと同じもの、無ければ同じ系列のものを選びます。

使うバージョンと `Effekseer.exe` の系列が違うと、`compile`・`upgrade`・`check-env` はエラーで止まります。

## 3. バージョンによって変わること

### 設定できる値の範囲

Effekseer のエディタは、選択肢にない数値が入ったファイルを開くと、その設定の欄を表示した瞬間に**クラッシュ**します
（しかもコンパイルは何も言わずに成功します）。このツールは、対象の系列に存在する値だけを受け付けます。

新しい系列で増えた主な値:

| 追加された系列 | 値 |
|---|---|
| 1.6 | 位置・拡大の種類の追加、位置の親子関係の種類の追加、モデルの参照方法 |
| 1.7 | フェードアウトの種類 2、グラデーション色、回転の種類 6（視点に向ける）、トリガーによる生成・削除、削除条件（KillRules） |
| 1.80 | テクスチャのミラー（Wrap=2）、方向ビルボード（Billboard=4）、回転の種類 7（速度方向に向ける）、トリガーの種類「親の削除」「親の衝突」、外部モデル、トリガーで発生、GPU パーティクル、衝突 |

1 つだけ注意が必要な変更があります。**テクスチャ UV の種類（`DrawingValues/TextureUVType/Type`）は 1.80 で番号が変わりました**
（1.7 以前は 1=タイル、1.80 は 1=パーティクルごとにタイル・2=タイル）。

選んだ系列に**項目自体がない**もの（1.7 向けに GPU パーティクル、1.6 向けにトリガーなど）は、エラーではなく警告になります。そのバージョンのエディタは、その項目を無視します。

### コンパイル結果

コンパイルした `.efkefc` のバイナリのバージョン番号が系列ごとに違います（[1 章](#1-対応しているリリース)の表）。
`compile` は、出力がその番号になっているかを確認します。

## 4. ゲームのランタイムとの互換性

Effekseer のランタイム（Unity 用、DX ライブラリ用などのプラグイン）は、**自分より新しいバイナリのバージョンのエフェクトを読み込みません**。
古いバージョンのエフェクトは、新しいランタイムで読み込めます。

| コンパイルした系列 | 1.5 ランタイム | 1.6 ランタイム | 1.7 ランタイム | 1.80 ランタイム |
|---|---|---|---|---|
| 1.5 | ○ | ○ | ○ | ○ |
| 1.6 | × | ○ | ○ | ○ |
| 1.7 | × | × | ○ | ○ |
| 1.80 | × | × | × | ○ |

設定ファイルの `project.runtime_version` にゲームのランタイムの系列（`1.5`・`1.6`・`1.7`・`1.80`）を書いておくと、
`install` が読み込めないエフェクトを拒否します。

## 5. ファイルの ToolVersion と自動変換

### Effekseer はファイルの ToolVersion を見て読み方を変える

`.efkproj` の中には、そのファイルを作ったツールのバージョン（`<ToolVersion>`）が書かれています。
Effekseer のエディタは、Effekseer のバージョンが上がって設定の書き方が変わるたびに、**`ToolVersion` が古いファイルを読み込むときだけ**、古い書き方を新しい書き方に自動で変換します。

つまり、

- `ToolVersion` が**古い**ファイルに**古い書き方**で書いた設定 → 変換されて正しく読まれる
- `ToolVersion` が**新しい**ファイルに**古い書き方**で書いた設定 → **黙って無視される**
- `ToolVersion` が**古い**ファイルに**新しい書き方**で書いた設定 → 変換で**上書きされる**

となります。このツールが作る設定は古い書き方なので、`new-project` はどのバージョンを選んでも `ToolVersion` を **`0.7CTP1`**（一番古い扱い）で作ります。
この形式なら、1.50RC1 〜 1.80.7 のどのエディタでも開けて、全部の設定が正しく読まれます。

### ツールが気をつけている変換

| この ToolVersion 以上のファイルでは | 無視される古い書き方 | 古いファイルで変換される先（上書きされる新しい書き方） |
|---|---|---|
| 1.50β3 | 歪み（`Distortion`）、モデルのライティング・法線テクスチャ（ノードに `RendererCommonValues` がある場合） | `RendererCommonValues/Material`、`NormalTexture` |
| 1.60α1 | UV アニメーションの各項目（`UVAnimation` 直下） | `UVAnimation/AnimationParams` |
| 1.60α3 | 重力・引力（`LocationAbsValues` の `Type`・`Gravity`・`AttractiveForce`） | `LocationAbsValues/LocalForceField4` |
| 1.70α1 | スプライト・モデルの色（`Sprite/ColorAll*`、`Model/Color*`） | `DrawingValues/ColorAll`（スプライト・モデルのノード） |
| 1.70α2 | トラックの色（`Track/Color*`） | `DrawingValues/TrailColor*`（トラックのノード） |
| 1.80β2 | 生成間隔・削除条件・トリガー（`CommonValues` の `GenerationTime*`・`RemoveWhen*`・`TriggerParam`） | `CommonValues/Generation`・`Removal` |

`validate`・`compile`・`upgrade` と、書き込むすべてのコマンドは、ファイルの `ToolVersion` に対して**間違った側の書き方**を見つけるとエラーで止めます。

補足: 次の 2 つは、項目が消えるわけではありませんが、`ToolVersion` によって見た目が変わることがあります。

- リボン・トラックの補間（`TrailSmoothing`・`TrailTimeSource`）: 1.70α1 より古いファイルでは「補間なし」に固定されます。
- `RendererCommonValues` があり `Lighting` の指定がないモデル: 1.50β3 より古いファイルではライティングありのマテリアルになります。

## 6. upgrade：新しい形式への変換

1.80 で追加された「トリガーで発生」（`Generation/Timing`=トリガー、`Trigger`、`TriggerCount`）は、
`ToolVersion` が 1.80β2 以上のファイルにしか書けません（古いファイルでは、読み込み時の変換で「連続して発生」に戻されます）。

そのために `upgrade` コマンドがあります。

```
python -m tools.effect upgrade work/Spark.efkproj --effekseer-version 1.80.7
```

`upgrade` は、ファイルを対象バージョンの `Effekseer.exe` で一時的にコンパイルし、Effekseer が `.efkefc` の中に保存したエディタ用データを `.efkproj` として書き戻します。
変換は **Effekseer 自身の変換処理**なので、エディタで開いて保存したのと同じ結果になります。

変換後のファイルについて:

- `ToolVersion` はそのエディタのバージョン（例: `1.80.7`）になり、そのバージョン以降のエディタでしか開けません。
- 古い書き方でしか作れないオプション（スプライト・モデルの `--color`、`--track-color` など）は使えなくなります。
  色などは `upgrade` の前に設定するか、`--set` で新しい書き方の項目名（例: `DrawingValues.ColorAll.Fixed.R=255`）を指定してください。
- `add-node` の `--generation-time`・`--trigger-*` と、Python の `presets.common_values(layout="v180")` は新しい書き方で書き込みます。

## 7. どうやって確かめたか

- **全 33 リリースで実行**: 各リリースの `Effekseer.exe` で、テスト用のエフェクトのコンパイル、出力のバージョン番号、
  新しすぎる `ToolVersion` の拒否、[5 章](#5-ファイルの-toolversion-と自動変換)の変換のチェック、`upgrade` の往復を確認しました。
- **設定値の範囲**: 各リリースの `EffekseerCore.dll` から、エディタの選択肢の一覧（列挙型の値）を直接読み出して、ツールの表と照合しました。
  同じ系列のリリースは、すべて同じ値の範囲でした。
- **変換のチェック**: ツールが作る設定を、変換のしきい値の `ToolVersion` ごとにコンパイルし、Effekseer が `.efkefc` に保存したエディタ用データを
  `0.7CTP1` でコンパイルした結果と比べました。**違いが出る（設定が消える）ものはすべて検出され、違いが出ないものは検出されない**ことを確認しています。

このテストは `selftest` に入っているので、`effekseer.cui_paths` に `Effekseer.exe` を登録すれば、自分の環境でも同じ確認ができます（[development.md](development.md)）。
